# Koeiro v0.13.0: 声の作り込み3機能と、同時通訳・AI変換の遅延整合の修正

## 🌟 ハイライト

* **音量の自動均一化（既定OFF）**
  小声を変換モデルが掴める音量まで持ち上げます。無音は上げません。「調整」② 変換の「入力の整え」カードにあり、停止中でも変換中でも切り替えられます。
* **AI出力のフォルマント（既定OFF）**
  AIの声の高さ（F0）は動かさず、共振だけを高域へ寄せて明るくします。AI Voice にだけ掛かり、Original・Female DSP・同時通訳は素通りします。
* **抑揚プリセットに「Feminine」を追加**
  幅広めの抑揚と語尾の上げで、女性寄りの読み方に寄せます。Auto Intonation をONにして選んだときだけ効き、既定の Anime Light はそのままです。
* **同時通訳が長い発話でも止まらなくなりました**
  話の区切りを待たず、3秒以上変わっていない部分までを読み上げて追いつきます。すでに読んだ文節は繰り返しません。
* **AI変換の50 msのズレを実測して修正**
  一括変換の出力が入力より50 ms遅れていました。実測値をコードの前提に反映しています。
* **実行ファイル（Koeiro.exe）で声の登録が実際に動くようになりました**
* **RAM空き容量を変換の打ち切り条件にしないようにしました**
* **更新の案内ダイアログで、ボタンが画面外に出なくなりました**

※ 既存の設定は引き継がれます。追加した3機能はすべて既定OFFなので、`settings.json` を作り直さない限り音は v0.12.0 と同じです。

## ➕ 追加した機能

### 音量の自動均一化（`src/processors/leveler.py`）

* 目標は RMS 0.1（-20 dBFS 相当）のゆっくりした追従で、上げも下げも ±12 dB まで。立ち上がり 0.5 秒、戻り 2 秒で、ブロック長ではなく時間定数で動きます。ゲインの床（-50 dB 相当）を下回るブロックではゲインを動かさないので、無音を持ち上げません。
* 掛かるのは入力側（デノーズ・ゲート・ゲインの手前、囁きモードの後ろ）です。ゲートの閾値と変換モデルが「一定の音量」で動く前提に揃えるためで、変換された声そのものの音量は変えません。
* OFFのときは1ビットも動かさない素通しです。

### AI出力のフォルマント

* 「② 変換」の末尾にカードを追加しました。持ち上げ量は +0.0〜+6.0 semitones、既定 +2.0です。
* 実装は Female DSP と同じネイティブ段を `mode='female_dsp'`・`pitch=0` で使うもので、ピッチ段は通しません。テストで「F0は動かず、スペクトル重心は上がり、利得は±1 dB以内に収まる」ことを押さえています（`tests/test_ai_formant.py`）。
* 切り替えはリアルタイムです。ネイティブ段は係数を作り替えるだけで、バッファ確保の再実行が要りません。
* **代償として遅延が増えます**。low_latency 品質の段は 48 kHz で 2048 samples（=42.7 ms）の後段遅延を持ちます。ON の間だけAI Voice の遅延に足されます。

### 抑揚プリセット「Feminine」

* 幅（range_expansion .60）・rise .40・onset_lift .45・語尾 .40 と、既存プリセットと同じノブだけで作っています。抑揚の仕組み自体は足していません。
* Auto Intonation がOFFのときはどのプリセットも効きません。本体の変換ルート（Original / Female DSP / AI Voice）の音は変えません。

## 🛠 改善・修正

### 同時通訳（実験②）

* **区切りを待たない読み上げ**: 部分認識のテキストが3秒変わらないままなら、言い切られていなくてもその時点までを読み上げます。モノローグで止まる問題の対策です。
* **重複しない**: 先に部分認識で読んだ文節は覚えておき、確定テキストが来れば未被読の後半だけを追加で読みます。
* **マイクが無音ならそう言います**: 入力が来ていないことを状態に出します（デバイス選択と音量のどちらかだと分かるように）。
* **48 kHz以外では動かないと明示**: サンプルレートを48 kHz以外にしているときは、待たせず「48 kHz専用」とステージに書きます（表示とアーム判定の両方で押さえました）。
* **ステージ大表示が経路ごとに正しい状態を言う**: 同時通訳ルートでは声のブリッジを意図的に止めたまます。以前の表示は「AIが読み込まれていない」と言っていましたが、今は翻訳ドライバーの状態（ASRの読み込み中・翻訳合成中・読み上げ結果・エラー）を出します。
* 音声認識の設定が壊れているときは、何も表示せず黙って止まるのではなく、その旨を書きます。

### AI変換の遅延整合（MeanVC2）

* 一括変換（標準ルート）の出力が入力より **50 ms遅れて**いました。入出力の対数エネルギー包絡の相互相関で実測すると、legacy frontend は出荷構成（group6 / vocoder36）で 1490 ms、group1 でも 530 ms かかり、前提値（1440 / 480 ms）よりどちらも +50 ms でした。aligned frontend は差ゼロです。
* 原因は、遅延線の長さ（リセット時に確保するサンプル数）と、frontend が実際に入力より後から出す50 msを、1つの数字にまとめていたことです。`buffer_frames_ms`（遅延線）と `frontend_latency_ms`（実測50 ms）を分け、`model_buffer_ms` を 1440 → 1490 ms に修正しました。修正後の一致度は 0.79 → **0.93**。測定と分解は `notes/meanvc2_alignment.md` に残しています。
* すべてオフライン計算です（音声デバイスは開いていません）。

### 声の登録（実行ファイル版）

* 登録プログラム `tools/register_voice.py` を、バンドル内ではなく **AI環境をセットアップしたインストール先ツリー**から探すようにしました。実行ファイルは `tools/` を同梱しないため、これまでは「can't open file」で落ちて「登録に失敗しました」しか出ていませんでした。
* 声ライブラリの根っこもインストール先ツリー優先にしました。凍結ビルドのバンドル内にある声一覧を見ていたため、登録できた声がGUIに現れないことがありました。
* 登録のログは書き込み可能なデータフォルダ（Windows では `%LOCALAPPDATA%\Koeiro\logs\voice-registration.log`）に出ます。失敗メッセージに実際のログパスを表示します。
* 新規登録の基準マニフェストを標準ボイスの `runtime.json` に変更しました（開発用の参照セット `models/meanvc2_ref20` はツリーから無くなっており、そこを参照していた登録は失敗していました）。

### 更新の案内ダイアログ

* リリースノートが長くなると「更新して再起動」のボタンが画面下に押し出されて押せなくなっていました（v0.13.0 の本文は約6,000文字）。ノートを画面高さに応じて上限のあるスクロール欄に表示し、ボタン3つはダイアログ本体に固定しました。声の登録ダイアログと同じ作り方です。
* マークダウンの記号（`#`・`**`・`[label](url)`）は落として読める平文にし、リリースページのURLを1行添えます。Esc は「後で」扱いになります。

### RAMプレッシャー

* 「空きRAMが足りないから発話変換を停止する」という打ち切りをやめました。ゲームと一緒に使っている、いちばん動いてほしい場面でアプリを止めていたためです。空き容量は観測してログと状態（`ram_pressure`）に出すだけにしています。
* ワーカーが逼迫した場合の挙動は変えていません：クラッシュまたは停止し、Original にフォールバックします。
* 声の登録前と登録中の RAM検査・RSSによる強制停止も削除しました。登録の15分タイムアウトはそのまま残しています。

### 開発者向け

* `requirements-dev.txt` に `obsws-python` を追加（PV撮影の `tools/obs_record.py` が使います）。
* `promo/` にプロモーション動画の Remotion ソースを追加しました。撮り素材・生成アセット・手元の声は git 管理外で、同梱されるのは構成とスクリプトだけです（`promo/README.md` 参照）。

## ⚠️ 既知の制限（未検証を含む）

* **聴感の確認は行っていません**。音量の自動均一化・AI出力のフォルマント・Feminine の効き目は、数値とテストで押さえたまでです。実際に動かして聞こえ方を確かめるのはお使いの耳です。
* **同時通訳の翻訳モデルは未実装**のままです（認識した文をそのまま英語TTSで読み上げます）。翻訳モデルは拡張パック側の枠として残しています。
* 同時通訳は48 kHz専用・ASRとTTSの導入が必要です。低スペックCPUでは実用的な速度が出ません（前版実測 RTF ≈ 5.7）。
* AI出力のフォルマントはONの間だけ遅延が増えます（+42.7 ms）。リアルタイム通話で気になる量です。一括変換側は影響しません。
* 実機（マイク・Discord）での長時間の連続運転試験は行っていません。短時間のStart/Stopとモード切替の確認までです。

## 📦 アップデート手順

アプリ内蔵の自動更新（「調整」③ アプリ）から v0.13.0 を適用するのが最短です。手動の場合は：

1. リリース添付の `koeiro-v0.13.0-windows.zip` / `koeiro-v0.13.0-linux.tar.gz` を展開し、そのフォルダで1回だけ環境を作ります
   （Windows: `py -3.12 tools/setup_release.py` / Linux: `python3.12 tools/setup_release.py`）。
2. 既存の仮想環境（`.venv`・`vc_models/meanvc2/.venv`・`vc_models/post_lavasr`）は引き継がれ、再ダウンロードは発生しません。
3. 声の登録を使う場合、実行ファイル版は AI環境のあるインストール先ツリーが必要になります（`KOEIRO_ROOT` か `koeiro-root.txt` で解決されます）。
