# Koeiro v0.12.0: 実験室（実験的な追加機能）とオプション機能の配線

> GitHub Releases の本文にそのまま貼れる下書きです。公開前に `src/version.py` の
> `APP_VERSION` を `0.12.0` に更新してから `git tag v0.12.0` を打ってください
> （PUBLISHING.md「GitHubリリース配布」参照）。

## ハイライト

- **画面を「ステージ1枚＋引き出し」に再編**しました（DESIGN.md §4）。常設面はステージ
  （入力レベルの1本・3点リレー・遅延の数値・Start）だけになり、マイク・話し方・音量・加工・
  診断は右上の「調整」、追加機能は「実験」の引き出しに入りました。右から重なるので、
  設定を触っている間もステージの数値は隠れません。ページ切替（ボイスチェンジ / 設定 /
  実験室）と中央のオーブは廃止し、右下に浮いていたガイドボタンはヘッダに移しました。
  声リストは右のままですが、ヘッダの「声リスト」で幅0に畳めます（畳むとステージが広がります）。
- **「調整」を3つのバンドに分けました**（① 配線 / ② 変換 / ③ アプリ）。バンドは見出しだけでなく、
  その下に並ぶカードの入れ物です。カードが後から組み立てられる順で別の見出しの下に紛れ込むことが
  なくなり、見出しが約束するのはその下にあるカードだけになりました。
  - 並び: ① 配線（マイク / 出力先 / モニター / 音の規格）→ ② 変換（入力の整え / 声と話し方 /
    声の加工（Female DSP）/ 声の微調整 / 抑揚補正 / 出力の仕上げ）→ ③ アプリ（シーン /
    アプリの更新 / Discord / 診断）。
  - 1つの決定は1枚のカードに寄せました。AI Voice の経路（Beatrice native Pitch・pre-roll・
    crossfade）は「声の微調整」へ、抑揚の詳細パラメータは「抑揚補正」へ戻し、
    **診断は計測値だけ**にしました（中に動かせる設定を混ぜない）。
- **実験室を1つのスイッチにまとめました**。既定はOFFで、まず機能名の一覧と各機能の
  ON/OFFだけが見えます。「実験機能有効」を入れてから使う機能だけをONにすると、
  その機能の中身が開きます。マスターOFFのまま機能をONにしても設定は保存される
  だけで、何も動きません（動いている機能を止めるスイッチが隠れないため）。
  切っても本体の変換ルート
  （Original / Female DSP / AI Voice）はそのまま動きます。
- **軽量TTS（Kokoro-82M）を任意導入**で使えるようにしました。GUI本体の環境は汚さず、
  専用環境 `vc_models/tts/.venv` で動きます。
- **ウィンドウ枠をアプリに統合**しました。OSのタイトルバーを使わず、上端から下端まで
  1枚の面に見せます。最小化・最大化・閉じるはバー右端にあり、バーの空白をつかむと
  ウィンドウが動き、ダブルクリックで最大化します。枠のリサイズ境界とポインタもアプリ側です。
  バー左端のアイコンと「Koeiro」の文字は廃止しました。
- **ステージの足元**を使うようにしました。右にアイコンとロゴを置きます（ロゴは白字アートの
  ためネイビーのチップの上）。AI の準備状況は Start 列の下の大表示に一本化し、足元には置きません。
  どちらも実測値だけで、進捗率のような見せかけの数値は出しません。
- 変換ルートの音は一切変えていません（元の声・Female DSP・AI Voice の並列スロットは据え置き）。

## 追加：実験室（①〜⑤）

| # | 機能 | できること | 既定 |
|---|------|-----------|------|
| ① | レイテンシ・ガバナ | コールバックが締切に間に合っているかを計測し、このPCに合う品質プロファイルを**提案**（反映は任意・停止中のみ） | ON（提案のみ） |
| ② | 同時通訳ボイス | 入力文を合成してWAVに書き出し。声色を寄せる（登録ボイスの明るさ・体格へ寄せる）も可。変換モードで「同時通訳」を選ぶと、話した日本語が英語音声になって出力先（Discordなど）へ流れる（文単位・遅延大・ASRとTTSが必要） | OFF |
| ③ | 囁きモード | 囁きを自動で見分けて周期成分（ピッチ）を与え、変換モデルが掴める入力にする。通常の声・無音・息の音はそのまま通す | OFF |
| ④ | 分散推論（LANのGPU機） | 別PCの `tools/remote_worker.py` に音声合成・翻訳を依頼 | OFF |
| ⑤ | 複数話者の自動振り分け | 声の高さと明るさで話者を見分け、話者ごとに別の声を割り当て。「識別テスト」は登録ボイスの参照音声で実測 | OFF |

- ①は**提案**が既定で、品質の自動変更は「停止中なら自動で反映する」を明示的にONにした時だけです。
- ②のTTSは **Kokoro-82M（Apache-2.0）× kokoro-onnx（MIT）**。重みは同梱せず、
  `tools/install_tts.py` で各自取得します（約140MB）。
- ④は認証がありません。**LAN内のみ**で使ってください。現状は音声合成・翻訳の依頼までで、
  声変換モデルそのもののLAN配信は未対応です。
- ⑤は「近い声は分けられない」という限界を隠さず表示します。

## 変更・修正

- **チュートリアルをスポットライトに描き替えました**（DESIGN.md §4 A-3）。中央の大きな窓をやめ、
  説明しているコントロールだけを暗幕の穴で明るく残し、その周りを線で囲みます。説明は対象の隣に
  置く 330px のカードで **1〜3行**、下に進捗と「戻る」（通常の色）と「次へ」（明るい塗り）。
  Esc でスキップ、←/→ で前後に進めます。ページを変えると実際の引き出し／声リストが開き、
  対象が画面外ならスクロールしてから線を引きます。
- **「調整」「実験」に検索と目次を付けました**（DESIGN.md §4 A-2）。引き出しの上に、その面の
  中身から組み立てた検索欄と、グループ名（① 配線 / ② 変換 / ③ アプリ など）の目次を置きます。
  目を押すとそのグループまでスクロールし、見ているグループを自分で示します。検索は**カード単位**で、
  **隠すだけで、表には出しません**（いまのモードや機能スイッチが隠しているものは、検索しても現れません）。
- **グループの見出しに絵文字を1つ**付けました（DESIGN.md §4 A-2）: 配線 🔌 / 変換 🎛 / アプリ ⚙️、
  実験の5機能は ⏱️ / 🌐 / 🤫 / 📡 / 👥。長い列は文字より形のほうが速く見つかるためで、
  ①〜⑤の番号は絵文字の後ろに残したままです。カードの見出しには付けていません
  （13枚に並べると色が散って、かえって探しづらくなるため）。
- **面の色をブランドネイビー `#284b7d` に一本化**しました。使い方は「その面の見出し」と
  「いま見ている面のバーのボタン」だけです（塗りには使いません）。変換中・フォーカス・
  主要ボタンも同じネイビーです。4 面バラバラの色は廃止しました。

- **TTSを専用環境で実行**: `vc_models/tts/.venv` のPythonを `python -m src.tts.service`
  で呼び、1リクエスト＝1プロセスでWAVを受け取る経路を追加しました。GUI本体の環境に
  `kokoro-onnx` が無くても②が動きます（本体の環境には重い依存を入れません）。
- **実行ファイルから自分のモデルを見つける**: `model_root()` を追加。凍結ビルド
  （`dist/Koeiro/Koeiro.exe`）は同梱物に `models/` を持たないため、ビルド時に記録した
  インストール先ツリー（`koeiro-root.txt`、`KOEIRO_ROOT` でも上書き可）から
  `models/tts/` と `vc_models/tts/.venv` を読みます。
- 実験室の書き出し先を `data_dir()/lab/` に変更（実行ファイルの中を書き換えないため）。
- ②の状態表示を正直にしました。翻訳モデルは拡張パック側の未実装枠のため、
  **今は入力文をそのまま読み上げます**（翻訳は将来のパック）。
- ②で使う「声色を寄せるボイス」は②カード内の専用コンボに移動しました。
- 「アプリの更新」カードは ③ アプリのバンドへ移りました。以前は設定面の上部に固定されており、
  画面再編のあとは ①配線の見出しの直下に出ていました。
- ステージの遅延説明と「診断」の内訳が**同じラベルを上書き**していて、ステージ側は空のままでした。
  いまはステージが「いずれもエンドツーエンドの実測値ではありません。」の1行を持つて、
  数値の内訳（Sample Rate / Buffer / 概算ブロック / PortAudio報告 / DSP内部遅延）は「診断」にあります。
- pre-roll の説明文は1か所（`_preroll_text()`）にまとめました。3か所に同じ文が書かれており、
  MeanVC2の経路は存在しない説明文ヘルパーを呼んでいました（標準ボイス以外を選ぶと例外）。
- **「出力の仕上げ」を② 変換の末尾に追加**しました（既定OFF）。逐次変換の出力だけに掛かる、
  つなぎ目のクリック除去と歯擦音の抑制（最大3dB）です。一括変換側は従来どおりワーカー内の
  仕上げが掛かります。効き目の数値は合成フィクスチャで測っていますが、聴感の最終確認は
  自分の耳でお願いします。
- **自動更新が壊れていたのを直しました**。配布物の版照合が `0.11.0` と `v0.11.0` を別物と
  判定し、すべての更新ダウンロードを拒否していました。あわせて展開時の経路 escape を検査します。
- **実験室のON/OFFは常に見える**ようにしました。マスターOFFでも各機能の見出しとスイッチは
  残り、中身（設定と実行ボタン）だけが閉じます。マスターOFFのまま機能をONにしても設定は
  保存されるだけで、何も動きません。

## 既知の制限（未検証を含む）

- **翻訳モデルは未実装**です（`notes/translation_pack.md` のパック枠）。②は現状
  パススルー翻訳＋TTSで、日本語文をそのまま英語TTSに読ませます。
- ②の速度は**低スペックCPUでは実用的とは言えません**。このPCでの実測は
  モデル読込 4.4秒・1.55秒の音声を 8.9秒で合成（RTF ≈ 5.7）です。GPU機での実測は未実施です。
- ②のライブ出力は**文単位の逐次通訳**です（話し終わりの無音で区切って翻訳・合成・再生）。
  日本語認識には `tools/install_asr.py` のモデル、英語合成には `tools/install_tts.py` が
  必要で、どちらも未導入だと状態表示に出ます。被せ気味に話すと追いつきません。
- **聴感・体感遅延は未計測**です。書き出したWAVは必ず自分の耳で確認してください。
- ③④⑤の実機（変換しながら）での動作確認は、短時間のStart/Stop・切替チェックまでです。
  長時間の連続運転試験は行っていません。
- 実験室の機能はすべて**オプション**です。壊れても本体の変換ルートには影響しません。

## アップグレード

1. リリースZIP/TARを展開し、そのフォルダで1回だけ環境を作ります
   （Windows: `py -3.12 tools/setup_release.py` / Linux: `python3.12 tools/setup_release.py`）。
2. 既存の仮想環境（`.venv`・`vc_models/meanvc2/.venv`・`vc_models/post_lavasr`）は引き継がれ、
   再ダウンロードは発生しません。`src/version.py` の固定が変わった版だけ再実行してください。
3. ②を使う場合のみ、追加で `tools/install_tts.py` を実行します
   （`models/tts/` と `vc_models/tts/.venv` が作られます）。

## 内部メモ（公開時は削除してください）

- 今回の作業で **声のモーフィング＋感情の連続制御（当時の⑤ 声の錬成）は実装せず取り消し**ました。
  未リリースのため配布物には含まれません（作成した試作モジュールは削除済み）。
- 凍結exeでは TTS の実行モジュール（`src.tts.service`）を**バンドルしていません**。
  専用環境がインストール先ツリーのPythonで `-m src.tts.service` として起動するためで、
  ASRワーカー（`src.asr.service`）と同じ扱いです。配布物からインストール先ツリーが消えると
  ②は動きません（他モデルと同じ前提）。
